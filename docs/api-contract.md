# Контракт внешнего HTTP API — ИИ-агент поддержки

> Статус: **ЧЕРНОВИК** для Г3a. Контракт внешних маршрутов, а не межмодульного API.
> Источники: `.specs/support-agent.md`, `GLOSSARY.md`, `adr/0001`–`adr/0008`, `docs/HACKATON_BRIEF.md`, `docs/ИИ_агент_поддержки.md`, `docs/ИИ-агент поддержки_QA.md`, решения владельца от 26.11.

## 0. Заморозка контракта и порты

> Контракт заморожен до начала волны 1 (26.11.2026).

### 0.1 Правило заморозки

Контракт, модель данных, схема миграций, роутер и ядро агента — общие поверхности. Внутри среза волны 1 они не меняются. Изменение возможно только через exec, с записью в журнал решений и пометкой ревизии контракта.

Агент, которому поверхность кажется неправильной, останавливается и передаёт вопрос exec. Самовольная правка замороженной поверхности останавливает работу среза.

### 0.2 Порты между срезами

Срезы волны 1 не импортируют код друг друга. Связь идёт через этот контракт.

| Порт | Владелец реализации | Форма |
|---|---|---|
| Ядро | срез «ядро» | `runAgent(input: NormalizedMessage): Promise<AgentOutcome>` |
| Доступ | срез «доступ» | `checkAccess(request): Promise<AccessDecision>` |
| Каталог | срез «импорт фида» | `catalog.search(query: string, filters: CatalogFilters): Promise<CatalogHit[]>` |
| Документы | срез «документы» | `renderQuote(quote: QuoteInput): Promise<RenderedDocument>` |
| MAX-канал | срез «MAX-адаптер» | `channels/max` с методами `start()`, `stop()` |
| Эмбеддинги | замороженная спецификация | HTTP-эндпоинт и формат ответа; каждый срез реализует свой клиент |

Подробное описание владения файлами, диапазонов миграций и правил параллельной работы — `docs/plans/wave-1.md`.

### 0.3 Структуры портов

```ts

  vendor?: string;
  categoryId?: string;

};

type QuoteInput = {

  customerName: string;
```

## 1. Границы

- Один процесс Node.js/TypeScript обслуживает веб-интерфейс и HTTP API.
- Наружу выставлен один HTTP API. Модули `catalog`, `knowledge`, `documents`, `policy`, `promises`, `telemetry` вызываются внутри процесса только через публичные `index.ts`.
- Маршруты из макетов Ивы — внешний контракт фронтенда и демо. Они не превращают внутренние модули в микросервисы.
- Каналы `web` и `MAX` нормализуют входящие сообщения в общий контракт ядра и отправляют результат через адаптер канала.
- `tenant_id` определяется сервером из сессии/кода доступа и не принимается из тела запроса.

**ДОПУЩЕНИЕ A-API-01:** все маршруты внешнего API обслуживаются Next.js Route Handlers; отдельный FastAPI-процесс не нужен. Заменяется решением владельца по стеку.

**ДОПУЩЕНИЕ A-API-03:** основной LLM-адрес — `https://opencode.ai/inference/go/v1/chat/completions` через OpenCode Go с моделью DeepSeek; запасной адрес задаётся отдельным URL из переменных окружения. Векторы — `https://opencode.ai/inference/go/openai/v1/embeddings`, модель `text-embedding-3-small`.

Факт проверки 26.11: `GET https://opencode.ai/inference/go/v1/models` без ключа вернул `200`; `POST .../embeddings` без ключа не ответил за 20 с и был прерван по тайм-ауту. Адреса и доступность проверяются повторно на задаче 1 с ключом владельца; при отличии фиксируются в ADR.

## 2. Соглашения

- Формат: `application/json; charset=utf-8`.
- Провенанс: JSON использует `snake_case`; внутренние TypeScript-типы используют `camelCase`. Преобразование выполняется на границе HTTP, не внутри модулей.
- Идентификаторы: UUID v4.
- Время: ISO 8601 UTC, например `2026-11-26T12:00:00.000Z`.
- Деньги: целые рубли; НДС и скидка вычисляются кодом.
- Идентификатор запроса: `X-Request-Id`; сервер создаёт его, если клиент не передал.
- Ответы об ошибках:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Понятное описание ошибки",
    "details": {},
    "request_id": "uuid"
  }
}
```

| HTTP | `error.code` | Когда |
|---|---|---|
| 400 | `validation_error` | Тело не прошло схему запроса |
| 401 | `unauthorized` | Нет действующего кода доступа/сессии |
| 404 | `not_found` | Обращение, источник или документ не найден |
| 409 | `conflict` | Конфликт состояния, например повторное одобрение |
| 413 | `payload_too_large` | Файл документа превышает лимит |
| 415 | `unsupported_media_type` | Формат документа не поддерживается |
| 422 | `approval_required` | Материал не опубликован и не доступен поиску |
| 429 | `rate_limited` | Превышен лимит запросов |
| 500 | `internal_error` | Непредвиденная ошибка |
| 502 | `upstream_error` | Ошибка внешнего API модели/эмбеддингов |
| 503 | `upstream_unavailable` | Внешний API временно недоступен |
| 504 | `upstream_timeout` | Истёк тайм-аут внешнего шага |

## 4. Контракт веб-чата

### Идентификация диалога

Диалог веб-чата определяется подписанной cookie `support_conversation` со значением только `conversation_id`. Cookie подписывается сервером; клиент не может задать или подменить `conversation_id` в теле запроса — значение в теле сверяется с cookie и при расхождении отклоняется `403`.

- Отсутствующая или невалидная подпись → создаётся новый диалог и выдаётся новая cookie.
- Cookie содержит только идентификатор диалога: имя, телефон, email, IP и другие данные не записываются.
- Идентификация по IP запрещена: два клиента с одинаковым IP получают разные диалоги.
- Cookie: `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`.

**ДОПУЩЕНИЕ A-API-04:** имя cookie и параметры `Secure`/`SameSite` фиксируются владельцем вместе с доменом стенда; до этого используется `support_conversation`, `HttpOnly`, `Secure`, `SameSite=Lax`.

### `POST /v1/chat`

Вход:

```json
{
  "conversation_id": "uuid",
  "message": {
    "client_message_id": "uuid",
    "text": "Сколько стоит KES на 50 устройств?"
  }
}
```

Поля `conversation_id` и `client_message_id` обеспечивают идемпотентность повторной отправки. `conversation_id` обязан совпадать с подписанной cookie; расхождение → `403`.

Ответ `200`:

```json
{
  "conversation_id": "uuid",
  "message_id": "uuid",
  "outcome": "respond",
  "answer": {
    "text": "Подтверждённый ответ со ссылкой на источник",
    "sources": [
      {
        "kind": "kb_article",
        "id": "uuid",
        "title": "Лицензирование",
        "location": "п. 3"
      }
    ]
  },
  "escalation": null,
  "trace": {
    "steps": 7,
    "tokens": 8500,
    "cost_rub": 5.8
  }
}
```

Допустимые `outcome`: `respond`, `escalate`.

При `outcome=escalate` поле `answer` равно `null`, поле `escalation` содержит:

```json
{
  "id": "uuid",
  "reason": "no_confirmed_source",
  "summary": "Краткое резюме для менеджера",
  "draft": "Черновик ответа без неподтверждённых фактов"
}
```

### Режим тени

При включённом режиме тени `/v1/chat` и MAX-адаптер:

- не отправляют ответ клиенту;
- возвращают только `outcome=escalate` с черновиком и эскалацией;
- фиксируют факт подавления ответа в трассе.

**ДОПУЩЕНИЕ A-API-02:** HTTP-ответ `/v1/chat` показывает `escalate` клиенту как технический результат; текст для конечного пользователя формируется веб-интерфейсом. Заменяется решением по UX.

## 5. Контракт ядра

### `POST /agent/run`

Вход — нормализованное сообщение:

```json
{
  "conversation_id": "uuid",
  "message_id": "uuid",
  "channel": "web",
  "external_chat_id": "string | null",
  "text": "Текст после маскирования",
  "masked_fields_count": 0
}
```

Ответ:

```json
{
  "outcome": "respond",
  "answer": {
    "text": "Текст с метками ПД",
    "sources": []
  },
  "escalation": null,
  "steps": [
    {
      "node": "retrieve",
      "endpoint": "GET /kb/search",
      "duration_ms": 300,
      "tokens_in": 0,
      "tokens_out": 0,
      "cost_rub": 0,
      "source_ids": ["uuid"],
      "outcome": null,
      "model": "deepseek"
    }
  ]
}
```

`channel` имеет значения `web`, `max`. Ядро не знает интерфейсов каналов. В шаге трассы `source_ids` содержит только идентификаторы опубликованных источников, `outcome` — результат узла, `model` — идентификатор модели без ключа.

## 6. Контракт базы знаний

### `GET /kb/search`

Параметры:

| Параметр | Тип | Обязательный | Значение |
|---|---|---|---|
| `q` | string | да | Вопрос, 1–2000 символов |
| `conversation_id` | uuid | нет | Контекст диалога |
| `limit` | integer | нет | 1–20, по умолчанию 5 |

Ответ `200`:

```json
{
  "matches": [
    {
      "article_id": "uuid",
      "chunk_id": "uuid",
      "title": "Лицензирование",
      "text": "Фрагмент источника",
      "location": "п. 3",
      "score": 0.91
    }
  ]
}
```

Инварианты:

- в выдачу попадают только одобренные документы и опубликованные статьи;
- `pending`, `draft`, `rejected` никогда не возвращаются;
- отсутствие подтверждённого источника — не пустой успешный ответ, а эскалация.

### `POST /kb/documents`

Используется `multipart/form-data`, поле `file`.

Допустимые типы: PDF, DOCX, Markdown, TXT. Другие форматы отклоняются `415 unsupported_media_type` без попытки разбора.

Ответ `202`:

```json
{
  "id": "uuid",
  "status": "pending",
  "filename": "licensing.pdf",
  "mime_type": "application/pdf",
  "chunks_count": 12
}
```

### `POST /kb/documents/{id}/approve` и `POST /kb/drafts/{id}/approve`

Тело:

```json
{
  "actor": "manager-id"
}
```

Ответ `200`: сущность со статусом `published`. Повторное одобрение возвращает `409 conflict`.

## 7. Формирование КП по шаблону заказчика

Шаблон: `Агент поддержки-20261126T080905Z-1-001/Агент поддержки/Шаблон КП ПАО Софтлайн.pdf`. Формирование КП — сверх обязательного минимума по ТЗ: клиент должен сначала согласиться с выбором, КП собирается как черновик на проверку менеджеру.

### 7.1 Поля документа

| Поле | Источник | Обязательность |
|---|---|---|
| Наименование заказчика | Данные клиента | Обязательное |
| Исходящий номер и дата | Код, дата формирования | Обязательное |
| Шапка ПАО «Софтлайн» с адресом и реквизитами | Фиксированный текст шаблона | Обязательное |
| Обращение «Уважаемый заказчик!» | Фиксированный текст шаблона | Обязательное |
| Таблица: Артикул, Наименование, Кол-во, Цена руб., Сумма руб., в т.ч. НДС руб. | Каталог и расчёт кодом | Обязательное |
| Строка «Итого» | Расчёт кодом | Обязательное |
| Формулировка о цене с учётом налогов | Фиксированный текст шаблона | Обязательное |
| Условия оплаты: предоплата или постоплата | Решение менеджера | Обязательное |
| Срок поставки | Решение менеджера или подтверждённый источник; по умолчанию — электронная лицензия в тот же рабочий день | Обязательное |
| Срок действия КП | Решение менеджера | Обязательное |
| Подписант: директор департамента | Фиксированный текст шаблона | Обязательное |

### 7.2 Правила

- Суммы, НДС и итог считает только код по данным каталога.
- Реквизиты подставляет код после ответа модели; модель не печатает реквизиты.
- Пустое обязательное поле — документ не создаётся, создаётся эскалация с причиной `document_field_missing`.
- Шаблон счёта заказчик не дал: счёт формируется по собственному шаблону команды, отдельно от КП.

**ДОПУЩЕНИЕ A-API-06:** срок поставки электронной лицензии — тот же рабочий день. Основание: заказчик от 26.11.2026 указал, что каталог меняется редко, в основном электронная поставка. Пока заказчик не подтвердит иначе, значение помечается как допущение в описании продукта.

## 8. Импорт источников базы знаний

### 8.1 Обход сайта `docs.softline.com`

Проверено 26.11.2026: сайт отдаёт серверный HTML, headless-браузер не нужен; `robots.txt` и `llms.txt` — 404; `sitemap.xml` — 302 на `/ru-ru/sitemap.xml`. Восемь корневых разделов: `id`, `lk`, `subscriptions`, `vendors`, `checkout`, `merchant-portal`, `payment`, `allsoft`. Суммарно 212 уникальных ссылок второго уровня, реальный объём статей — 200–500. Размер страницы 330–613 КБ при малом объёме текста.

Правила обхода:

- обход в ширину от восьми корневых разделов, глубина до трёх;
- дедупликация по URL;
- один запрос в секунду, никаких параллельных залпов;
- понятный `User-Agent` с указанием контакта;
- при `429` или `5xx` обход останавливается, работа продолжается на закэшированном материале.

Извлечение из страницы: заголовок, путь разделов, основной текст, URL источника, дата обхода. Сырой HTML сохраняется в кэш, чтобы сайт не дёргался повторно; в базу попадает только извлечённый текст.

### 8.2 Чанкование

- Размер чанка — 800–1200 знаков.
- В каждом чанке сохраняются заголовок и путь разделов.
- В каждом чанке хранится URL источника для цитирования.

### 8.3 Статус и провенанс

Источник, импортированный с сайта заказчика, получает статус `approved_by_customer` с провенансом и не проходит менеджерское одобрение. Материал, загруженный менеджером через интерфейс, требует одобрения — у него `status=pending` и пустой провенанс.

## 9. Контракт эскалации

### `POST /escalations`

```json
{
  "conversation_id": "uuid",
  "reason": "no_confirmed_source",
  "summary": "Резюме",
  "draft": "Черновик ответа",
  "sources": []
}
```

Причины первого вертикального среза:

- `no_confirmed_source` — в БЗ нет подтверждённого источника;
- `policy_denied` — условия вне полномочий агента;
- `upstream_error` — модель или эмбеддинги недоступны;
- `upstream_timeout` — истёк тайм-аут шага.

## 10. Лимиты и тайм-ауты

| Операция | Лимит |
|---|---|
| LLM до первого токена | 120 с |
| Внутренний шаг | 5 с |
| Весь диалог | 300 с |
| Повтор после 429 | один, через 30 с |
| MAX-сообщения | не более 2/с на диалог |
| Размер документа | 50 МБ |
| HTTP-запросы | 10/мин на IP |
| Диалоги | 50/день |

## 11. Доступ к стенду и ограничения

Публичный стенд доступен неделю после сдачи. Барьер доступа обязателен: без кода доступа чат не работает.

### 11.1 Код доступа

- Тип барьера: единый код доступа для жюри; выдаётся в описании продукта.
- Код вводится на отдельной странице `/access` и проверяется сервером.
- Код хранится только в переменных окружения/секретнице; в коде и репозитории его нет. Сравнение — constant-time.
- Успешная проверка выдаёт подписанную cookie `support_access` со сроком действия, заданным владельцем.
- Cookie содержит только идентификатор сессии доступа, срок действия и привязку к коду; сам код и его хеш в cookie не попадают.
- Cookie привязана к коду: перевыпуск cookie не обнуляет счётчики. Смена кода инвалидирует ранее выданные cookie.
- `POST /v1/chat`, `POST /agent/run` и остальные маршруты ядра без действующей cookie `support_access` возвращают `401 unauthorized`.
- Защищаются: страница чата, `POST /v1/chat`, отправка ответа в MAX. Кабинет менеджера — тот же барьер и отдельный код менеджера.
- В журналах и трассе нет кода доступа и токенов.

### 11.2 Ограничения

| Ограничение | Поведение при достижении | Значение |
|---|---|---|
| Запросы в минуту на IP | `429 rate_limited` | 10 |
| Диалоги в сутки на стенд | `429 rate_limited`; 51-й диалог не стартует | 50 |
| Бюджет модели на стенд | Новые вызовы модели запрещены; текущие диалоги завершаются без новых вызовов; пользователь получает «лимит демо исчерпан, попробуйте позже» | 300 ₽/сутки и 30 ₽/час |
| Размер одного запроса | `413 payload_too_large` | 4000 символов |

Счётчик диалогов — серверный, он не привязан к cookie. Счётчик запросов в минуту считается по IP.

### 11.3 Учёт расхода

Фактические расходы считаются по трассе: токены и стоимость каждого шага. Счётчик бюджета обновляется после каждого вызова модели. Ошибка `429` или `402` от провайдера не увеличивает счётчик повторно: стоимость неуспешного вызова равна нулю, если провайдер не сообщил о списании.

Проверяемые ожидания: без кода чат не работает; повторный ввод кода в новой вкладке не обнуляет лимиты; 11-й запрос в минуту отклоняется; 51-й диалог за сутки не стартует; при исчерпании бюджета пользователь получает понятное сообщение, а не ошибку сервера; в журналах нет кода и токенов.

## 12. Неизменяемые части

- Суммы считает только код.
- Валидатор цифр не пропускает ответ, если сумма или цитата не совпали с источником.
- В модель передаются только метки ПД; таблица соответствий не покидает серверную часть.
- Отсутствие подтверждённого источника или полномочий приводит к эскалации, а не к выдуманному ответу.
- Токены и секреты не появляются в ответах API, трассе, репозитории или доказательствах.

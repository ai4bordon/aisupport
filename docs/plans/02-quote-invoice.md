# Документы: КП и счёт — план реализации

> **Для исполнителей:** обязательный навык: superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans — выполнять план по задачам. Шаги отмечаются флажком (`- [ ]`).
>
> **Статус: ЧЕРНОВИК — не исполнять до Г3a волны 1 и отдельного «поехали» владельца.**

**Цель:** черновик коммерческого предложения по шаблону ПАО «Софтлайн» и счёт по собственному шаблону команды. Формирование КП — сверх обязательного минимума по ТЗ: клиент сначала соглашается с выбором, КП собирается как черновик на проверку менеджеру.

**Архитектура:** Модуль `documents` принимает готовую структуру расчёта `QuoteInput` и подставляет её в текстовый шаблон. PDF собирается на сервере, поэтому документ одинаково выглядит на записи и у жюри. Каталог не импортируется: числа приходят во входной структуре.

**Технологии:** Node.js 22 LTS, TypeScript, PostgreSQL 16, `node-pg-migrate`, генератор PDF на сервере.

**Тикет:** `.scratch/support-agent/issues/02-quote-invoice.md`

**Спецификация:** `.specs/support-agent.md` (копия трекера: `.scratch/support-agent/spec.md`); контракт: `docs/api-contract.md` §7 и §0.3; данные: `docs/data-model.md` §3.16–§3.17; шаблон: `Агент поддержки-20261126T080905Z-1-001/Агент поддержки/Шаблон КП ПАО Софтлайн.pdf`; план волны: `docs/plans/wave-1.md`.

## Команда проверки

`npm run test -- tests/integration/02-quote-invoice.test.ts`

Команда обязательна к приёмке среза. Юнит-тесты среза — обязательные шаги плана; интеграционный тест собирает их вместе и проверяет срез целиком.

## Общие ограничения

- Код создаётся только в спринте 26.11 19:00 → 28.11 19:00 по Камчатке, после Г3a и отдельного «поехали».
- Срез владеет каталогом `src/modules/documents/**`, `src/app/api/docs/**`.
- Общие поверхности не меняются: `docs/api-contract.md`, `docs/data-model.md`, роутер, `package.json`, `tsconfig.json`, `next.config.ts`, `vitest.config.ts`.
- Миграция этого среза — `3000_templates_documents.sql`. Номера закрепляет exec.
- Суммы, НДС и итог считает только код. Реквизиты подставляет код после ответа модели; модель реквизиты не печатает.
- Пустое обязательное поле — документ не создаётся, а даётся ошибка `document_field_missing`.
- Пул тестовых процессов ограничен: `vitest --pool=forks --poolOptions.forks.maxForks=2`.

## На что обратить внимание при проверке

- В готовом документе не остаётся незаполненных плейсхолдеров шаблона.
- НДС и итог совпадают с входным расчётом; расхождение блокирует документ.
- Условия оплаты, срок поставки и срок действия КП — обязательные поля, без них документ не создаётся.
- Подписант «Директор департамента» присутствует в КП по шаблону.
- Номер документа уникален в пределах тенанта и связан с обращением.

```ts
type RenderedDocument = {
  kind: "quote" | "invoice";
  number: string;
  pdfPath: string;
  amount: number;
};

type DocumentError = {
  code: "document_field_missing" | "amount_mismatch";
  field: string | null;
};
```

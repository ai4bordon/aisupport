# Импорт фида каталога: план реализации

> **Для исполнителей:** обязательный навык: superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans — выполнять план по задачам. Шаги отмечаются флажком (`- [ ]`).
>
> **Статус: ЧЕРНОВИК — не исполнять до Г3a волны 1 и отдельного «поехали» владельца.**

**Цель:** загрузить товарный фид заказчика в базу и научиться искать по каталогу структурно, без векторного индекса.

**Источник истины:** живой фид `https://store.softline.ru/feeds/Softline.yml.gz` — полный каталог. Проверено 26.11.2026: URL отвечает `200`, отдаёт gzip (сигнатура `1f8b`). Локальный файл `Mindbox.yml.gz.xml` (292 МБ, 136 040 позиций, дата внутри `2026-11-25 14:12`) — снимок для офлайн-разработки и демо.

**Регламент обновления:** по ответу заказчика от 26.11.2026 фид обновляется несколько раз в сутки, но заказчику достаточно обновления раз в сутки — каталог меняется редко, в основном электронная поставка. Значит: импорт запускается вручную, планировщик в прототипе не строится. В описании продукта и на демо: каталог актуален на дату снимка, обновление — раз в сутки, импорт запускается вручную.

Оценка заказчика «около 200 000 позиций» — исходный ориентир для проекции, а не фактическое число: в проверенном снимке от 25.11.2026 — 136 040 позиций. Ключ импорта — только `offer/@id`; `vendorCode` у части записей пустой и не уникальный, поэтому по нему позиции не различаются.

Импорт идёт по живой ссылке: файл качается по HTTP потоково, gzip распаковывается на лету, в память не грузится целиком. Обновление каталога — суточная процедура с ручным запуском, без планировщика. Повторный импорт — идемпотентный upsert по `offer/@id`: позиция обновляется, а не дублируется. Дата фида и хеш снимка пишутся в провенанс, чтобы на демо было видно актуальность каталога. Если живой фид недоступен, импорт работает на последнем снимке — это не ошибка демо.

**Архитектура:** Скрипт импорта разбирает YML построчно и пишет позиции пачками в одной транзакции. Поиск — структурный: точный артикул, полнотекст по названию, фильтры по вендору, категории, наличию и параметрам. Вектор у каталога не применяется.

**Технологии:** Node.js 22 LTS, TypeScript, PostgreSQL 16, `node-pg-migrate`, Vitest.

**Тикет:** `.scratch/support-agent/issues/12-import-catalog-feed.md`

**Спецификация:** `.specs/support-agent.md` (копия трекера: `.scratch/support-agent/spec.md`); контракт: `docs/api-contract.md`; данные: `docs/data-model.md` §3.6–§3.8; план волны: `docs/plans/wave-1.md`.

## Общие ограничения

- Код создаётся только в спринте 26.11 19:00 → 28.11 19:00 по Камчатке, после Г3a и отдельного «поехали».
- Срез владеет каталогом `src/import/catalog/**`, `src/modules/catalog/**`, `scripts/import-feed.ts`.
- Общие поверхности не меняются: `docs/api-contract.md`, `docs/data-model.md`, роутер, `package.json`, `tsconfig.json`, `next.config.ts`, `vitest.config.ts`.
- Миграции этого среза — `1000_catalog.sql` и `1010_clients_orders_licenses.sql`. Номера закрепляет exec.
- Файл фида читается потоково: HTTP-загрузка с распаковкой gzip на лету; загрузка 292 МБ в память запрещена.
- Живой фид `https://store.softline.ru/feeds/Softline.yml.gz` — источник истины; локальный снимок — основа для офлайн-разработки и демо.
- Регламент обновления — раз в сутки, ручной запуск импорта. Планировщик, cron и фоновая задача в прототипе не строятся.
- Импорт фида и обход сайта базы знаний не запускаются одновременно — тяжёлые прогоны выполняет exec по одному.
- Пул тестовых процессов ограничен: `vitest --pool=forks --poolOptions.forks.maxForks=2`.

## На что обратить внимание при проверке

- Позиция без `offer_id` пропускается и учитывается в отчёте, а не падает весь импорт.
- Повторный импорт той же позиции обновляет её, а не создаёт дубль.
- Импорт с живого фида идёт потоково по HTTP с распаковкой gzip на лету; при недоступности фида работа идёт с последнего снимка и это не ошибка.
- Позиция с нулевой ценой возвращается в поиске, но помечается как «цена не подтверждена заказчиком».
- `available=true` означает наличие в датированном снимке фида, а не текущий склад или срок поставки; карточка показывает дату снимка.
- Каждая карточка сохраняет провенанс файла и снимка: дата фида и хеш.
- Поиск по запросу, которого нет в каталоге, возвращает пустой список, а не выдуманную позицию.
- Значения параметров сохраняются как есть, без нормализации: фильтр по параметру идёт по точному имени параметра.

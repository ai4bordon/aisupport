# Требования exec к тикетам 12 и 13 — материал для spec

> Статус: **черновик exec.** Тикеты 12 и 13 создаёт и оформляет spec. Этот документ содержит проверенные факты и требования, чтобы формулировки AC и провенанса в тикетах совпали с планами `docs/plans/12-import-catalog-feed.md` и `docs/plans/13-import-knowledge-site.md`.

## Тикет 12 — Импорт фида каталога

**Заголовок:** `12 — Импорт товарного фида каталога и структурный поиск`

**Blocked by:** замороженный контракт `docs/api-contract.md` и `docs/data-model.md`, не тикет 01. Тикет выполняется параллельно тикету 01.

**Тип:** task. **План:** `docs/plans/12-import-catalog-feed.md`.

**Цель:** загрузить товарный фид заказчика в базу и обеспечить структурный поиск по каталогу без векторного индекса.

**Проверенные факты (26.11.2026, файл `Mindbox.yml.gz.xml`, 292 МБ):**

| Факт | Значение |
|---|---|
| Позиций (`offer`) | 136 040 |
| Категорий (с `parentId`) | 9 311 |
| Вендоров | 1 232 |
| Имён параметров | 387 |
| Значений параметров | 1 903 038 |
| `available=true` | 44 601 |
| Ненулевая цена | 55 771 |
| Валюта | RUR |

Поля позиции: `id`, `group_id`, `name`, `vendor`, `vendorUrl`, `url`, `price`, `oldprice`, `currencyId`, `categoryId`, `available`, `delivery`, `pickup`, `description`, параметры (`Версия`, `Срок действия`, `Тип лицензии`, `Модель лицензирования`, `К-во пользователей до`, `Тип продукта` и другие).

**AC:**

1. Импорт фида создаёт 136 040 позиций и 9 311 категорий; полный путь категории вычислен при импорте.
2. Значения параметров сохраняются как есть; фильтр по параметру работает по точному имени параметра.
3. Позиция без `offer_id` пропускается и учитывается в отчёте; прерванный импорт продолжается по файлу состояния.
4. Поиск по каталогу структурный: точный артикул, полнотекст по названию, фильтры по вендору, категории с подкатегориями, наличию и параметрам.
5. У позиций каталога нет вектора; векторный индекс применяется только к базе знаний и статьям.
6. Позиция с нулевой ценой возвращается с пометкой «цена не подтверждена заказчиком».
7. Поиск по отсутствующему запросу возвращает пустой список, а не выдуманную позицию.

**Команда проверки:** `npm run test -- tests/integration/12-import-catalog-feed.test.ts`

**Свидетельства:** отчёт импорта с числами из таблицы; выборка из пяти позиций, совпадающая с фидом; примеры поиска и фильтров; отсутствие вектора у каталога в схеме.

**Провенанс:** источник — фид заказчика `Mindbox.yml.gz.xml` от 25.11.2026, путь `Агент поддержки-20261126T080905Z-1-001/Агент поддержки/`. Каталог импортирован как данные заказчика; цены из фида — данные заказчика, а не подтверждённые коммерческие условия, поэтому позиции с нулевой ценой помечаются как неподтверждённые.

**Риск для владельца:** машина 4 vCPU и 8 ГБ. Импорт фида и обход сайта базы знаний не запускаются одновременно — тяжёлые прогоны выполняет exec последовательно.

## Тикет 13 — Импорт базы знаний с сайта заказчика

**Заголовок:** `13 — Импорт базы знаний с сайта заказчика с провенансом`

**Blocked by:** замороженный контракт `docs/api-contract.md` и `docs/data-model.md`, не тикет 01. Тикет выполняется параллельно тикету 01.

**Тип:** task. **План:** `docs/plans/13-import-knowledge-site.md`.

**Цель:** получить материалы сайта `docs.softline.com` и страницы `store.softline.ru/delivery_info/` как источники базы знаний — с провенансом, готовые к цитированию, без ручного одобрения.

**Проверенные факты (26.11.2026):**

| Факт | Значение |
|---|---|
| `robots.txt` | 404 |
| `llms.txt` | 404 |
| `sitemap.xml` | 302 на `/ru-ru/sitemap.xml` |
| Корневых разделов | 8: `id`, `lk`, `subscriptions`, `vendors`, `checkout`, `merchant-portal`, `payment`, `allsoft` |
| Уникальных ссылок второго уровня | 212 |
| Размер страницы | 330–613 КБ при малом объёме текста |
| Формат ответа | серверный HTML, headless-браузер не нужен |

**AC:**

1. Обход идёт в ширину от восьми корневых разделов, глубина до трёх, дедупликация по URL, один запрос в секунду, понятный `User-Agent`.
2. Из страницы извлекаются заголовок, путь разделов, основной текст, URL источника и дата обхода; в базу попадает только извлечённый текст, сырой HTML хранится в кэше.
3. При `429` или `5xx` обход останавливается с указанием причины, а уже собранные страницы импортируются.
4. Повторный запуск обхода берёт кэш и не обращается к сайту.
5. Чанки имеют размер 800–1200 знаков; в каждом сохранены заголовок, путь разделов и URL источника для цитирования.
6. Импортированный источник имеет `status=approved_by_customer` и непустой провенанс; он не проходит менеджерское одобрение, потому что это материалы, которые заказчик сам дал как базу знаний. Материал, загруженный менеджером через интерфейс, одобрение проходит.
7. Каждый чанк цитируем: в ответе агента виден URL источника.

**Команда проверки:** `npm run test -- tests/integration/13-import-knowledge-site.test.ts`

**Свидетельства:** отчёт обхода с числом просмотренных и импортированных страниц; пример источника с заголовком, путём разделов, URL и провенансом; пример чанка с URL; остановка обхода при `429` с сохранением собранного.

**Провенанс:** `docs.softline.com, обход 26.11.2026` — фиксируется в источнике при импорте. Страница `store.softline.ru/delivery_info/` импортируется как отдельный источник с происхождением `store_page`.

**Риск для владельца:** обход не должен превышать нагрузку на сайт заказчика. Один запрос в секунду, никаких параллельных залпов; при `429` обход останавливается, а не ускоряется.

# Web и MAX используют общее ядро; опрос для спринта

По решению владельца Web и MAX — оба обязательных клиентских канала — используют общий контракт адаптера канала и одно ядро. MAX-бот `@se15151074_bot` опубликован, но серверная часть отсутствует; спринт и демо используют Long Polling (`GET /updates`, `message_created`) и отправку ответа через `POST /messages` на `https://platform-api.max.ru`. `https://botapi.max.ru` — проверенный рабочий алиас; `platform-api2.max.ru` неверен. Режим тени не отправляет ответ в MAX. Webhook (`POST /subscriptions`) требует публичного HTTPS с доверенным TLS; согласно `docs/HACKATON_BRIEF.md` §15 выделенный стенд появляется к дедлайну спринта, поэтому webhook не является приёмочным сценарием демо без подтверждённого более раннего TLS-хоста. Токен выдаёт владелец напрямую исполнителю; он никогда не попадает в файлы, журналы или материалы подтверждения. Основание: решения владельца и проверка Bot API исполнителем/супервизором.


### [B18] Диалоги MAX не пишутся в `messages` — канал живёт только в трассе
- **Где:** `scripts/max-worker.ts` — путь обработки входящего; `src/channels/max/adapter.ts`
- **Severity:** P1 · **Статус:** подтверждено (наблюдение на живом стенде: `conversations` по каналу `max` есть, `agent_steps` 64 шага, `messages` для диалога пусты)
- **Путь достижимости:** сообщение в MAX → воркер → ядро → ответ отправлен (журнал воркера: 12 строк «ответ отправлен в чат 611193671») → в `messages` ни клиентской, ни ответной строки.
- **Последствие:** лента MAX на `/start`, очередь менеджера и `last agent message` в идемпотентной ветке веб-чата не видят историю канала; аналитика по каналу неполная.
- **Почему это баг:** единый контракт «диалог = сообщения + трасса» заявлен в модели данных; веб-канал пишет `messages`, MAX — нет.
- **Текущий код:** воркер пишет шаги через `telemetry`, но не вызывает вставку в `messages`.
- **Исправленный код:** в обработчике перед вызовом ядра — `INSERT INTO messages (tenant_id, conversation_id, client_message_id, role, text_masked, text_original, sources)` с `client_message_id` из MAX `mid`; после ответа — строка `role='agent'` с восстановленным текстом.
- **Объяснение:** без персистенции канал не наблюдаем ни в кабинете, ни в демо-ленте.

### [B19] Доверие `x-forwarded-for` без флага — обход лимита запросов
- **Где:** `src/middleware.ts:50-58` — `clientIp`
- **Severity:** P1 · **Статус:** подтверждено (ветка `fix/audit-access-gate`, коммит `67aa8db`)
- **Путь достижимости:** любой клиент шлёт `x-forwarded-for: <случайный IP>` на каждый запрос → `clientIp` берёт первое значение без проверки прокси → счётчик 10/мин на IP не достигается → обход лимита расхода модели.
- **Последствие:** лимиты `R11`/`R17` не защищают от abuse; это ровно тот риск, ради которого барьер ставился.
- **Почему баг, а не решение:** договорённость была «доверять заголовку только при `ALLOW_PROXY_HEADERS`», реализация доверяет всегда; тест `audit-access-gate.test.ts:112` сам подставляет XFF и закрепляет небезопасное поведение.
- **Текущий код:** `if (forwarded) return forwarded.split(",")[0].trim();`
- **Исправленный код:** `if (process.env.ALLOW_PROXY_HEADERS === "1") { ... }` иначе — `request.ip`/адрес соединения; тест на два случая (флаг есть/нет).
- **Объяснение:** заголовок подконтролен клиенту, пока прокси его не перезаписал.

## 3. Находки

### [A1] Виджет генерирует новый `conversation_id` на каждое сообщение — второй ход всегда 403
- **Где:** `src/app/widget/chat.tsx:50` — `send()`
- **Severity:** P0 · **Статус:** подтверждено
- **Путь достижимости:** браузер открывает `/widget` → первое сообщение уходит с новым UUID → сервер выдаёт cookie `support_conversation` → второе сообщение снова генерирует UUID → `src/app/api/chat/route.ts:69` сверяет тело с cookie → `403 forbidden` → виджет показывает «Не удалось обработать запрос».
- **Как заметить:** написать в виджете два сообщения подряд.
- **Последствие:** веб-чат работает один ход за сессию; сценарии подбора (уточняющие вопросы) и обещания в вебе недемонстрируемы.
- **Почему это баг:** контракт §4 требует сверки тела с cookie; клиент сам её нарушает.
- **Текущий код:**
  ```ts
  body: JSON.stringify({
    conversation_id: crypto.randomUUID(),
    message: { client_message_id: crypto.randomUUID(), text: message },
  }),
  ```
- **Исправленный код:**
  ```ts
  // id диалога берём из cookie, если она есть; новый — только для первого хода
  const conversationId = readCookie("support_conversation") ?? crypto.randomUUID();
  body: JSON.stringify({
    conversation_id: conversationId,
    message: { client_message_id: crypto.randomUUID(), text: message },
  }),
  ```
- **Объяснение:** сервер уже связал диалог с cookie; клиент обязан её соблюдать, иначе сверка даёт 403.

### [A2] Страница `/access` отправляет form-urlencoded, маршрут ждёт JSON — барьер доступа не работает
- **Где:** `src/app/access/page.tsx:44` — `<form action="/api/access" method="post">`; `src/app/api/access/route.ts:31` — `request.json()`
- **Severity:** P0 · **Статус:** подтверждено
- **Путь достижимости:** жюри открывает `/access` → вводит код → нативная отправка формы (`application/x-www-form-urlencoded`) → `request.json()` бросает → `400 validation_error` → cookie не выдаётся.
- **Как заметить:** ввести корректный код на странице доступа.
- **Последствие:** жюри не может войти на стенд через штатную страницу; тест `tests/access/access.test.ts:61` шлёт JSON, поэтому расхождение не ловится.
- **Почему это баг:** §11.1 контракта обещает вход по коду на этой странице.
- **Текущий код:**
  ```ts
  let payload: unknown;
  try { payload = await request.json(); } catch { return errorResponse(400, ...); }
  ```
- **Исправленный код:**
  ```ts
  const contentType = request.headers.get("content-type") ?? "";
  const payload = contentType.includes("application/json")
    ? await request.json().catch(() => null)
    : Object.fromEntries((await request.formData()).entries());
  ```
- **Объяснение:** либо страница должна слать `fetch` с JSON, либо маршрут принимать форму; сейчас стороны разошлись в формате.

- **Исправленный код:** уникальный индекс `(conversation_id, trace_ref, is_shadow)` + `ON CONFLICT DO NOTHING RETURNING`; при отсутствии строки — исключение.
- **Объяснение:** ошибка превращена в успех.

### [C18] Текст обещания формирует код, игнорируя формулировку модели
- **Где:** `src/core/promise-extract.ts:336-348` — `promiseSentence`
- **Severity:** P2 · **Статус:** подтверждено
- **Путь достижимости:** модель обещает «пришлю расчёт и коммерческое предложение» → клиент получает «Счёт будет отправлен».
- **Последствие:** обещание в журнале и в чате не совпадает с намерением.
- **Почему баг:** семантика потеряна, хотя SSOT соблюдён.
- **Текущий код:** жёсткие шаблоны.
- **Исправленный код:** сохранять исходную фразу модели в `promises.text` и отправлять её после проверки срока.
- **Объяснение:** код должен проверять, а не переписывать обязательство.

### [C19] Маркер обещания удаляется только первым вхождением
- **Где:** `src/core/promise-extract.ts:306-313` — `stripPromiseMarker`, `replace` без `g`
- **Severity:** P2 · **Статус:** подтверждено
- **Путь достижимости:** два маркера или маркер не в начале строки → служебная строка уходит клиенту.
- **Последствие:** внутренний формат виден клиенту.
- **Почему баг:** комментарий обещает удаление маркера.
- **Текущий код:** `text.replace(/^\s*ОБЕЩАНИЕ:.*$/m, ...)`.
- **Исправленный код:** флаг `gm` и удаление всех вхождений.
- **Объяснение:** частичное удаление хуже отсутствия.

### [C20] Cookie диалога без срока жизни; битый percent-encoding роняет запрос
- **Где:** `src/core/session.ts:59` (`decodeURIComponent`), `:74` (`buildSetCookie`)
- **Severity:** P2 · **Статус:** подтверждено
- **Путь достижимости:** `Cookie: support_conversation=%E0%A4%A` → `URIError` вне `try` → 500; без `Max-Age` диалог и маска теряются при закрытии браузера.
- **Последствие:** 500 на недоверенном заголовке; потеря истории.
- **Почему баг:** функция обещает «null при неверной cookie».
- **Текущий код:** прямой `decodeURIComponent`.
- **Исправленный код:** `try { decodeURIComponent } catch { return null }`; добавить `Max-Age` (например, 7 дней) и зафиксировать в контракте.
- **Объяснение:** разбор недоверенного ввода не должен бросать.

### [C21] Дефолт `ESCALATION_MODE = off` расходится с ADR-0014
- **Где:** `src/core/escalation-mode.ts:25`; `.env.example:28`
- **Severity:** P2 · **Статус:** гипотеза (возможен осознанный выбор для демо)
- **Путь достижимости:** стенд без переменной → вопросы без источника не попадают в очередь менеджера.
- **Последствие:** потеря лида; поведение расходится с описанным в ADR.
- **Почему баг:** модуль сам называет `off` режимом локальной отладки.
- **Текущий код:** `DEFAULT_ESCALATION_MODE = "off"`.
- **Исправленный код:** `notice` как продуктовый дефолт, `off` — только явно.
- **Объяснение:** дефолт должен быть безопасным для бизнеса.

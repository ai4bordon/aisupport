# 01 — Веб-чат: ответ из базы знаний или эскалация менеджеру

Status: open
Blocked by: none (initial frontier)
Type: task
Priority: tracer bullet
Spec: `.specs/support-agent.md` requirements R1, R4, R5, R8, R14
Plan: `docs/plans/01-web-chat-kb-escalation.md` (черновик роли `exec`; требует G3a)

## Цель

Первый запускаемый вертикальный срез: сообщение клиента в веб-чате → один ответ из утверждённых синтетических знаний со ссылкой на источник либо эскалация менеджеру, если утверждённого источника нет. В этом тикете нет MAX и административной части. Эскалацию менеджеру разрешается проверить через минимальное внутреннее представление данных/CLI/API; полноценную административную часть здесь создавать не нужно.

## Объём

- Однопроцессный API на Node/TypeScript и минимальные точки сопряжения модуля `module/index.ts`, необходимые для среза.
- Веб-адаптер с подписанной cookie диалога, содержащей только `conversation id`; не идентифицировать клиентов по IP.
- Минимальные `knowledge.search`, маршрутизация ядра, результат `policy`/эскалации и трассировка действий.
- Явная токенизация PII на этом пути до вызова LLM; для первоначального демонстрационного сценария — только синтетические тестовые данные из белого списка.
- Известные факты возвращаются со ссылкой на утверждённый источник. При отсутствии совпадения или сбое провайдера создаётся эскалация, а не предположительный ответ.

## Критерии приёмки

1. Новый диалог веб-чата отправляет вопрос и получает ответ, подтверждённый опубликованным синтетическим источником со ссылкой на источник.
2. Вопрос, ответ на который отсутствует в утверждённых знаниях, создаёт запись эскалации с причиной, `conversation id`, сводкой и трассировкой; клиенту не отправляется ни один неподтверждённый факт.
3. Второй запрос с подписанной cookie возобновляет тот же диалог; отсутствующая или новая cookie создаёт отдельный диалог. Общие IP клиентов не объединяют диалоги.
4. Тестовые входные данные с именем, организацией, адресом, телефоном, адресом электронной почты, налоговыми/банковскими/паспортными данными передают на границу модели только токены; таблица соответствий и секреты не журналируются. Исходящая проверка отклоняет необработанные PII.
5. Трассировка записывает упорядоченные операции ядра, идентификаторы источников, результат и измеренные длительность/использование модели, когда они доступны; учётные данные отсутствуют.
6. В этот тикет сквозного среза не включены код/сценарий MAX или полный интерфейс администратора для менеджеров. Это не исключает ни то, ни другое из обязательного объёма функции.

## Команда проверки

`npm run test -- tests/integration/01-web-chat-kb-escalation.test.ts`

План должен сохранять выполнимость этой команды или заменить её эквивалентной целевой командой до G3a, если выбранный тестовый раннер использует другой синтаксис.

## Свидетельства ручной демонстрации

Используйте синтетические тестовые данные с утверждённым источником: выполните один вопрос с совпадением и один без него. Зафиксируйте ответ со ссылкой на источник, затем постановку эскалации в очередь, не включив секреты или необработанные PII. Сохраните вывод теста/код выхода вместе со свидетельствами плана.

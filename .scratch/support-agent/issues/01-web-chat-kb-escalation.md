# 01 — Веб-чат: ответ из базы знаний или эскалация менеджеру

Status: open
Blocked by: none (initial frontier)
Type: task
Priority: tracer bullet
Spec: `.specs/support-agent.md` requirements R1a, R1b, R4, R5, R8, R14, R26; ADR-0012, ADR-0014, ADR-0017
Plan: `docs/plans/01-web-chat-kb-escalation.md` (черновик роли `exec`; требует G3a)

## Цель

Первый запускаемый вертикальный срез: сообщение клиента в веб-чате → один ответ из утверждённых синтетических знаний либо эскалация менеджеру, если утверждённого источника нет. Источник и его URL остаются в `answer.sources`, трассе и кабинете менеджера; клиентский текст URL не содержит. В этом тикете нет MAX и административной части. Эскалацию менеджеру разрешается проверить через минимальное внутреннее представление данных/CLI/API; полноценную административную часть здесь создавать не нужно.

## Объём

- Однопроцессный API на Node/TypeScript и минимальные точки сопряжения модуля `module/index.ts`, необходимые для среза.
- Веб-адаптер с подписанной cookie диалога, содержащей только `conversation id`; не идентифицировать клиентов по IP.
- Минимальные `knowledge.search`, маршрутизация ядра, результат `policy`/эскалации и трассировка действий.
- Явная токенизация PII на этом пути до вызова LLM; для первоначального демонстрационного сценария — только синтетические тестовые данные из белого списка.
- Известные факты возвращаются с идентификатором/названием источника; URL источника сохраняется во внутренних источниках ответа, трассе и кабинете менеджера, но не отправляется клиенту. При отсутствии совпадения или сбое провайдера создаётся эскалация, а не предположительный ответ.

## Критерии приёмки

1. Новый диалог веб-чата отправляет вопрос и получает ответ, подтверждённый опубликованным синтетическим источником; `answer.sources` содержит источник и URL, а `answer.text` не содержит `http://` или `https://`.
2. Вопрос, ответ на который отсутствует в утверждённых знаниях, создаёт запись эскалации с причиной, `conversation id`, сводкой и трассировкой; клиенту не отправляется неподтверждённый факт или URL.
3. Второй запрос с подписанной cookie возобновляет тот же диалог; отсутствующая или новая cookie создаёт отдельный диалог. Общие IP клиентов не объединяют диалоги.
4. Тестовые входные данные с именем, организацией, адресом, телефоном, адресом электронной почты, налоговыми/банковскими/паспортными данными передают на границу модели только токены; таблица соответствий и секреты не журналируются. Исходящая проверка отклоняет необработанные PII.
5. Трассировка записывает упорядоченные операции ядра, идентификаторы источников, результат и измеренные длительность/использование модели, когда они доступны; учётные данные отсутствуют.
6. В этот тикет сквозного среза не включены код/сценарий MAX или полный интерфейс администратора для менеджеров. Это не исключает ни то, ни другое из обязательного объёма функции.

7. Интерфейс веб-чата использует токены палитры и стек шрифтов по R26; цветовые значения задаются через CSS custom properties, а не жёстко прописаны в компонентах. Логотип в шапке — официальный вариант с корректным фоном и охранным полем.

## Команда проверки

`npm run test -- tests/integration/01-web-chat-kb-escalation.test.ts`

План должен сохранять выполнимость этой команды или заменить её эквивалентной целевой командой до G3a, если выбранный тестовый раннер использует другой синтаксис.

## Свидетельства ручной демонстрации

Используйте синтетические тестовые данные с утверждённым источником: зафиксируйте ответ без URL в клиентском тексте, непустой `answer.sources` с внутренней ссылкой и постановку эскалации в очередь. Не включайте секреты или необработанные PII.

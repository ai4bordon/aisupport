# 11 — Защита публичного демонстрационного стенда

Status: open
Blocked by: замороженный контракт (docs/api-contract.md, docs/data-model.md)
Type: task
Spec: `.specs/support-agent.md` requirements R17, R26; ADR-0009, ADR-0012
Plan: `docs/plans/11-public-demo-access.md`

## Цель

Защитить публично доступный в течение недели после сдачи демонстрационный стенд от несанкционированного использования и неконтролируемых расходов модели.

## Критерии приёмки

1. Страница чата, `POST /v1/chat` и отправка сообщений в MAX без действующей серверной авторизации не запускают ядро/модель; кабинет менеджера требует дополнительный код менеджера.
2. Успешный ввод единого кода доступа выдаёт подписанную cookie, связанную с текущей версией кода. Код хранится только в переменной окружения; смена кода отзывает старые cookie; повторный ввод кода/открытие новой вкладки не создаёт новую квоту.
3. Запросы 11 и далее с одного IP в минуту отклоняются безопасным ответом; 51-й новый диалог на стенде за сутки не запускается. Суточный счётчик серверный и общий для всех cookie.
4. Потолки расхода модели 300 ₽/сутки и 30 ₽/час применяются атомарно при конкурентных запросах. При достижении часового предела новые диалоги не стартуют; уже текущие могут завершиться, но не вызывают модель повторно и возвращают понятное сообщение «Лимит демо исчерпан, попробуйте позже» вместо ошибки сервера.
5. Повторная обработка ответа провайдера 429/402 не списывает пользовательский лимит повторно; повтор запроса ограничен одной попыткой по R16.
6. Коды доступа, подписи cookie и токены отсутствуют в логах и свидетельствах проверки.

7. Страница ввода кода, заголовок и favicon оформлены по R26; страница использует утверждённые токены и шрифты, а логотип сохраняет разрешённый вариант и охранное поле.

## Команда проверки

`npm run test -- tests/integration/11-public-demo-access.test.ts`

## Свидетельства

Детерминированно проверить отказ до авторизации; успешный вход и сохранение квоты при новой вкладке; граничные значения лимитов; конкурентное достижение потолка; понятный ответ клиенту; отсутствие секретов в журналах. Не раскрывать реальные коды или токены в выводе теста.

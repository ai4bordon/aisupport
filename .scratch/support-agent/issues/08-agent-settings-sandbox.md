# 08 — Конфигурация агента, песочница, история и аудит

## Цель

Предоставить принятую поверхность настроек агента для менеджера с честным функциональным состоянием, изолированными тестовыми сессиями, историей и аудитом конфигурации.

## Критерии приёмки

1. Менеджер может просматривать/изменять поддерживаемые настройки `provider`/`model`/`endpoint`, `tools`/`skills`/`MCP`, параметров `prompt`, лимитов и общего состояния режима тени; следующий новый диалог использует сохранённую конфигурацию.
2. Любая настройка, отображаемая как доступная, функциональна; неподдерживаемые элементы управления явно отключены/обозначены как нереализованные, а не выглядят работающими.
3. Диалоги в песочнице вызывают настроенного агента изолированно и никогда не отправляют сообщения в веб-чат/MAX, не изменяют клиентский диалог, не создают видимые клиенту обещания и не влияют на аналитику рабочего окружения.
4. История хранит конфигурацию/версию, результат/оценку и данные о токенах/затратах для каждой тестовой сессии.
5. Аудит записывает субъекта, изменённую настройку, время и безопасные значения до/после; секреты редактируются и никогда не хранятся открытым текстом в аудите/журналах.

## Команда проверки

`npm run test -- tests/integration/08-agent-settings-sandbox.test.ts`

## Свидетельства

Продемонстрируйте одно изменение конфигурации, изолированный запуск в песочнице, запись в истории и запись аудита с отредактированными секретами.
